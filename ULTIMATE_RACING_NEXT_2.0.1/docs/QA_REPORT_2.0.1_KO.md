# ULTIMATE RACING 2.0.1 — Drift Chassis Rotation Fix

## 요약

이번 수정의 직접 원인은 드리프트 각도 계산 자체가 아니라 **플레이어 차량 렌더링에 그 각도가 적용되지 않던 연결 누락**이야.

## 원인 분석

`updateCar()`는 드리프트 중 `driftAngle`을 계산하고 있었고, 차량의 이동 방향은 `vehicleYaw + driftSlip`으로 처리하고 있었어. 하지만 마지막 차체 렌더링은 `car.rotation.y = vehicleYaw`만 적용했어. 그래서 차량은 옆으로 미끄러지는 계산을 하더라도 눈에 보이는 차체는 추가 드리프트 각도만큼 회전하지 않았어.

AI 차량은 이미 `setAICarPose()`에서 `yaw + rival.driftAngle`을 적용하고 있었지만, 플레이어 차량만 이 처리가 빠져 있었어. 플레이어와 AI의 표시 방식이 서로 달랐던 거야.

## 수정 내용

1. 플레이어 차체 yaw를 `vehicleYaw + driftAngle`로 적용했어.
2. 드리프트 차체 목표 각도를 기존 0.185rad(약 10.6°)에서 차량 핸들링에 따라 0.34–0.43rad(약 19.5–24.6°) 범위로 높였어. 기준 차량은 0.38rad(약 21.8°)야.
3. 드리프트 진입 시간상수는 0.14초, 해제 후 복귀 시간상수는 0.22초로 부드럽게 보간해.
4. 카메라의 전방 벡터도 차체 yaw를 따라가도록 수정했어.
5. 도로 가장자리 여유 폭과 플레이어-AI 충돌체 외곽 계산도 같은 차체 yaw를 사용해, 화면상 차체 방향과 충돌/도로 경계 계산이 서로 어긋나지 않도록 했어.
6. 드리프트 중 앞바퀴 시각 조향량을 0.20에서 0.27로 높였어.
7. Three.js를 사용할 수 없어 Canvas 2D 호환 모드로 실행되는 경우에도 차체 회전이 보이도록 보간된 `carVisualAngle`을 추가했어.

## 드리프트 회전 수치 검사

| 항목 | 결과 |
|---|---:|
| 기존 플레이어 차체 추가 드리프트 각도 | 0.185rad (10.6°) 계산됐으나 렌더링 미적용 |
| 새 기준 차체 드리프트 각도 | 0.380rad (21.8°) |
| 차체 목표 범위 | 0.34–0.43rad (19.5–24.6°) |
| 입력 좌우 대칭 | 통과 |
| 드리프트 각도 목표의 95% 도달 | 약 0.419초 |
| 해제 후 복귀 시간상수 | 0.22초 |
| 일반 주행 시 드리프트 오프셋 | 0rad |

이 수치는 순수 각도/보간 함수 테스트 값이며, 수동 조작으로 측정한 실주행 회전각이 아니야.

## 실제 실행 검증의 한계

이 환경에서는 Chromium/Three.js 전체 3D 장면의 실시간 키보드 주행을 끝까지 확인하지 못했어. 따라서 실제 게임에서 사용자가 느끼는 드리프트 조작감, 실제 평균/최소 FPS, GPU 및 메모리 사용량은 **미측정**이야. 자동 수치 테스트 통과를 실제 3D 플레이 테스트 통과로 간주하지 않았어.

이번 수정은 기존 키네마틱 주행 구조에서 플레이어 차체의 드리프트 각도가 표시되지 않던 문제를 고친 것이며, 강체 물리 엔진으로 전면 교체한 것은 아니야.
