# ULTIMATE RACING 1.9.0 — 4단계 작업 및 QA 보고서

작성일: 2026-11-23  
대상: 1.8.0 원본 프로젝트에서 분기한 1.9.0 작업본  
원본 백업: `ULTIMATE_RACING_NEXT_1.8.0_SOURCE_BACKUP.zip`

## A. 변경 사항

### 차량 속도 및 코너링

- 원본 코드에는 `277`이라는 수치가 하드코딩되어 있지 않았다.
- 원인은 코너링 능력에 따라 목표 최고속도에 `0.72`를 곱하던 보정이었다. 기본 차의 속도 기준과 다른 배수를 적용하면 계기판 환산값이 약 277km/h에 머무르는 것처럼 보일 수 있었다.
- 해당 고정 상한을 제거했다. 코너 하중은 `cornerTractionState()`에서 횡가속도 이용률, 종방향 접지 여유, 타이어 스크럽으로 연속 계산한다.
- 플레이어와 AI 모두 동일한 코너 접지 함수에 차량별 그립·핸들링 프로필을 전달한다.
- 고정 시간 간격은 120Hz이며 렌더 프레임당 최대 12회 물리 업데이트로 catch-up을 제한한다.

### 가드레일

- 가드레일에 가까워졌다는 사실만으로 속도 손실을 주지 않는다.
- `resolveRoadEdgeContact()`가 실제 도로 경계 바깥으로 향하는 이동을 감지할 때만 안전한 도로 범위로 clamp하고, 충돌 반응 1.2m/s와 0.42초 cooldown을 적용한다.
- 경계 안쪽으로 돌아서는 이동이나 근접 주행은 속도 손실 0이다.
- AI에도 도로 경계 clamp가 유지된다.

### 차량 충돌

- 플레이어-AI 및 AI-AI 접촉은 공통 `resolveRacerCollision()`을 사용한다.
- 질량은 차체 폭·길이 프로필에서 산출하고 반발계수 0.14의 종방향 임펄스를 적용한다.
- 이전/현재 종방향·횡방향 위치를 함께 사용하는 `sweptPlanarContact()`를 적용해 프레임 사이 대각선 교차를 검사한다.
- 같은 질량의 예제 충돌에서 운동량 보존을 확인했다.
- 실제 차량 이동은 여전히 스플라인 기반 키네마틱 모델이다. 강체 물리엔진으로 전면 교체한 것은 아니다.

### 드리프트

- 기본 드리프트 게이지 충전률: `0.145 → 0.173`으로 증가했다. 기본 충전률 기준 +19.31%다.
- 45m/s·풀 조향 품질 보정 시 +16.19%, 56m/s에서는 +19.31%다.
- 입력 키, 조향 및 최소 속도 조건은 유지해 일반 주행에서의 수동 충전을 막는다.
- 드리프트 회전 반응의 시간 상수를 0.38초로 두어 일반 조향 0.24초보다 더 묵직하게 만들었다.
- 드리프트의 회전 반응 계수는 1.22이며 기존 미끄러짐 효과를 유지한다.

### AI 그랑프리 순위

- 레이스 종료 시 완주 여부와 실제 finishTime으로 완주자를 정렬한다.
- 미완주자는 공통 84%가 아니라 각 참가자의 실제 누적 진행도로 DNF 단계와 진행률을 표시한다.
- 커리어 동점 기준은 총점 내림차순 → 누적 완주 시간 오름차순 → 우승 횟수 내림차순 → 실제 기록된 최고 랩타임 오름차순이다.
- DNF에는 포인트를 부여하지 않는다.
- 기록이 없는 최고 랩타임은 임의의 값 대신 `BEST —`로 표시한다.

- 기존 무료 차량 10대는 무료로 유지하고 총 20대 구성을 유지한다.
- 신규 구매 차량 가격:

- 완주 1회당 30% 확률로 추가 40코인을 지급한다(총 120코인).
- 보너스 발생 시 결과 패널 강조 애니메이션, BONUS REWARD 문구, 코인 효과음을 재생한다.

## C. 충돌 단위 테스트 결과

- 예제 입력: 같은 차체 질량, 충돌 전 플레이어 30m/s / AI 20m/s, 반발계수 0.14.
- 충돌 후: 플레이어 24.3m/s / AI 25.7m/s.
- 총 종방향 운동량: 충돌 전 51.136364, 충돌 후 51.136364.
- 대각선 스윕 교차, 현재 겹침, 분리된 차량 미충돌 판정 테스트 통과.
- 2D 스윕 테스트에서 이전 프레임과 현재 프레임의 종·횡 위치를 모두 사용한다.

위 수치는 공통 충돌 함수의 통제된 단위 테스트 결과다. 실제 3D 차량이 충돌한 뒤 계측한 값은 아니다.

## D. 그랑프리 및 보상 테스트

- 완주자: 실제 finishTime 오름차순.
- DNF: 실제 진행거리 내림차순.
- 예제 순위 결과: RIVAL-01(60.50s) → YOU(62.25s) → RIVAL-02(66.20s) → RIVAL-03(DNF, STAGE 3 2%).
- 커리어 동점 테스트 순서: points → fastest total time → wins → best lap.
- DNF 포인트 0, 중복 분류 저장 차단.
- 그랑프리 7회 연속 우승 정산 테스트에서 하루 제한 없이 7건 모두 정상 지급됐다.
- 타임어택 기본 80, 보너스 40, 중복 run ID 지급 차단 테스트 통과.
- 100,000회 고정 난수 표본에서 보너스 발생률 29.98%.

## E. 1시간 가상 물리 helper soak

※ 가상 시간 테스트이며 실제 브라우저를 1시간 실행한 것은 아님.

| 측정 항목 | 결과 |
|---|---:|
| 가상 주행 시간 | 3,600초(1시간) |
| 물리 스텝 | 432,000회(120Hz) |
| 충돌 임펄스 검사 | 3,600회 |
| 2축 스윕 검사 | 3,600회 |
| 드리프트 분기 진입 | 143,936 ticks(33.32%) |
| 실제 경계 접촉 모델 이벤트 | 1,860회 |
| 가드레일 근접 검사 | 60회, 속도 손실 0 |
| 실제 접촉/cooldown 검사 | 60회 |
| 속도 범위 | 0.2792–106m/s |
| 최대 속도 환산 | 381.6km/h |
| 실행 벽시계 시간 | 약 0.685초 |
| Node 프로세스 CPU 시간 | 약 0.730초 |

이 soak는 실제 생산 코드의 접지, 2축 스윕, 충돌 임펄스, 도로 경계 helper를 결정론적 S자 주행 루프에서 호출한다. 3,600초의 가상 상태를 432,000회 업데이트했다. Chromium/Three.js 전체 게임, AI 차량 전체 트래픽, 지형 메시, 브라우저 저장, 렌더링 및 GPU를 1시간 실행한 것이 아니다. CPU/heap도 Node 테스트 프로세스의 값이지 게임의 성능 계측값이 아니다.

## G. 미실행 및 남은 한계

- Chromium headless 구동을 시도했지만 60초 제한 안에 DOM 결과를 얻지 못해 실행 검증은 완료하지 못했다. Three.js 모듈은 jsDelivr 및 unpkg CDN에서 가져오는 구조다.
- 실제 3D 게임의 1시간 플레이 테스트: 미실행.
- 평균/최소/최대 FPS: 미측정.
- 게임 자체 CPU/GPU 사용량 및 메모리 누수: 미측정.
- Windows EXE 빌드 및 실행: 미실행. 해당 런타임 의존성 설치 및 Windows 실행 환경이 없었다.
- 산·바위·벽의 개별 3D 메시 콜라이더 검증: 미실행. 주행은 여전히 스플라인 기반 키네마틱 구조이므로 모든 지형 메시가 완전한 강체 충돌체라고 주장하지 않는다.
- 상점/결과 화면 버튼의 실제 브라우저 클릭 테스트: 미실행. 구매, 저장, 보상 로직은 VM 기반 자동 테스트와 정적 UI 검사로 확인했다.

## 최종 평가

- 277km/h의 코너별 고정 상한: 코드상 제거, 단위 테스트 통과.
- 가드레일 근접 자동 감속: helper 테스트에서 제거 확인, 실제 접촉 반응 유지.
- 플레이어/AI 충돌 공정성: 공통 임펄스 함수 적용, 통제 예제에서 운동량 보존.
- 드리프트: 충전 +16.19~19.31%, 무거운 조향 반응 적용.
- 순위: 실제 완주 시간과 진행도, career tie-break 순서 테스트 통과.
- 경제: 2,000코인 가격 상한, 타임어택 80/120 보상, GP Daily Limit 제거 및 idempotency 테스트 통과.
- 게임 전체 안정성: 코드/헬퍼 자동 검증은 통과했으나 실제 3D 브라우저 및 1시간 실기동 검증은 미완료.
